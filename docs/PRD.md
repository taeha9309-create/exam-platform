## 1. 한 줄 요약
강의실에서 노트북으로 치르는 시험에서, **브라우저 이탈과 브라우저 안의 AI 사용 흔적을 실시간으로 감지해 감독관에게 알리고, 감독관이 확인·조치한 과정을 기록으로 남기는** 웹 시험 플랫폼.

## 2. 문제

### 2.1 누구의 어떤 상황인가
- **교수자·조교(감독관)**: 강의실에서 노트북/PC로 시험을 치르게 하면, 수십 명의 화면 안에서 무슨 일이 일어나는지 볼 수 없다. 학생이 다른 탭에서 ChatGPT를 열거나 브라우저 사이드바에서 AI를 켜도, 감독관은 교실 앞에서 그것을 알아챌 방법이 없다.
- **정직한 학생**: 부정행위가 퍼지면 성적의 공정성이 무너진다. 반대로 지나친 자동 처벌(예: 알림 팝업 때문에 포커스가 빠졌는데 자동 종료)은 억울한 피해자를 만든다.

### 2.2 판단 근거 (뉴스·조사)
| 근거 | 내용 | 이 프로젝트에 주는 의미 |
|---|---|---|
| 국내 대학 AI 부정행위 연쇄 보도 (2025.11~) | 연세대 비대면 과목(약 600명) 중간고사에서 생성형 AI 집단 부정행위 적발. 고려대·홍익대·서울시립대·아주대·건국대 등에서 비대면·대면 시험 중 AI 사용, AI 스마트안경 착용 사례 보도 [1][2] | 문제가 실제로, 여러 대학에서, 반복적으로 일어나고 있다 |
| 연세대 사례의 감독 방식 | 시험 중 화면·얼굴 영상을 제출하게 했는데도 집단 부정행위가 발생 [1] | **감시(녹화)만으로는 부족**하다. 신호를 모아 사람이 실시간으로 확인하는 구조가 필요하다 |
| 대면 시험(고사장)으로 확산 | 초소형 카메라로 문제를 외부 전송, 스마트워치로 답을 받은 사례 [3] | 강의실 시험도 안전하지 않다 → **강의실 시험을 대상으로 한 근거** |
| 대학의 대응 한계 | 소수 감독관이 다수 수험생을 관리, 인력·예산 한계, 가이드라인 미비 [4][5] | 감독관에게 **"지금 어디를 봐야 하는지"** 알려주는 도구가 필요하다 |
| 영국 HEPI 학생 조사 (2025) | AI 도구 사용 학생 66% → 92%로 증가. 학생이 꼽은 1위 억제 요인은 "부정행위로 적발될 가능성"(53%) [6] | **"기록되고 있다"는 인식 자체가 억제 장치**다 → 사전 고지, "기록 중" 표시 |
| 미국 대규모 연구 (9.5만 명) | AI를 매일 쓰는 학생일수록 부정행위 비율이 높음. 금지만으로는 해결되지 않는다는 결론 [7] | 완벽 차단이 아니라 **억제 + 증거 + 사람의 판단**으로 접근 |

> 주: 기사마다 날짜·수치가 다르게 보도된 부분이 있어(예: AI 가이드라인 마련 대학 비율 22.9% vs 40%), 인용 수치는 원문 확인 후 사용한다.

### 2.3 문제 정의
> 강의실 노트북 시험에서 감독관은 학생 화면 안의 부정행위(다른 탭·앱 전환, 브라우저 내 AI 사용)를 볼 수 없고, 기존의 "N회 이탈 시 자동 종료" 방식은 놓치는 것도 많고 억울한 처벌도 만든다.

### 2.4 기술적 한계 (전제)
1. **AI 사용 여부를 확정적으로 탐지하는 것은 불가능하다.** 이 서비스는 "AI를 썼다"고 판정하지 않고, 관찰된 행동(이탈, 사이드바 열림 의심 등)만 기록·표시한다.
2. 웹 페이지는 휴대폰, 스마트워치, AI 안경 같은 **다른 기기**를 볼 수 없다. 이는 현장 감독과 시험 규정의 영역이다.
3. 웹 페이지는 설치된 브라우저 확장 프로그램 목록을 볼 수 없다. 확장·사이드바 AI는 **흔적 기반 감지**만 가능하며, 일부는 실험으로 가능 여부를 확인해야 한다.
4. **감지 코드는 학생의 브라우저에서 실행된다.** 개발자 도구나 확장 프로그램을 다룰 줄 아는 학생은 감지 이벤트를 끄거나 조작할 수 있다. 서비스는 "신호가 끊기는 것" 자체(하트비트 공백, 이벤트 순번 누락)를 신호로 삼아 보완하지만, 완전한 방어는 전용 브라우저(SEB)나 관리형 PC의 영역이다.
5. **전체화면은 강제할 수 없다.** 브라우저는 사용자 클릭이 있어야 전체화면에 들어가게 하고, ESC로 언제든 해제된다. 서비스는 "전체화면 진입 요구 + 해제 감지 + 재진입 안내"만 할 수 있다.
6. **OS 단축키(Alt+Tab, Win 키 등)는 가로챌 수 없다.** 그 결과로 생기는 포커스 상실만 감지한다.
7. **붙여넣기 차단은 완전하지 않다.** 키보드·메뉴 붙여넣기와 드래그 앤 드롭은 막을 수 있지만, 확장 프로그램이 직접 입력하는 텍스트나 자동 완성은 막을 수 없다.
8. 백그라운드 탭에서는 브라우저가 타이머를 늦춘다. 이탈 시간은 타이머가 아니라 **떠난 시각과 돌아온 시각의 차이**로 계산한다.

## 3. 해결 방법

### 3.1 핵심 아이디어
1. **알리고 → 사람이 확인하고 → 조치하고 → 기록한다.** 시스템은 판정하지 않는다.
2. **소수 감독관을 위한 실시간 대시보드.** 학생별 카드(학번·이름)에 신호가 즉시 표시되고, 확인이 필요한 학생이 위로 올라온다.
3. **"기록되고 있다"는 인식을 억제 장치로 활용.** 사전 고지·동의와 응시 중 "기록 중" 표시.
4. **감지 기능의 효과를 정직하게 검증.** 우회 시나리오를 직접 시도해 무엇이 잡히고 무엇이 안 잡히는지 공개한다.

### 3.2 검토한 대안과 선택 이유
| 대안 | 판단 |
|---|---|
| 포커스 이탈 + N회 위반 자동 종료 (흔한 방식) | 오탐 시 억울한 처벌. → 1차에서 제외, 2차 옵션 후보(기본 꺼짐) |
| 전용 브라우저(Safe Exam Browser) 필수 | 같은 PC 안에서는 가장 강력하지만 개인 노트북 설치 부담·당일 장애 위험. → 고도화 과제 |
| 웹캠 감독·얼굴 인식 | 강의실에는 사람 감독관이 있어 효용이 낮고 개인정보 부담이 큼. → 제외 |
| AI 생성 글 판별기 | 오탐이 매우 높아 판정 근거로 부적합. → 제외 |
| 사후 검증(LLM 후속 질문), AI 내성 문항 점검, AI 허용·기록 모드 등 | 검토했으나 이번 프로젝트의 초점(행동 감지)과 다름. → 제외 |
| **웹 기반 + 행동 감지 + 감독관 실시간 확인** | 학생은 링크만 열면 되고, 강의실 감독관과 결합해 오탐 피해를 줄인다. → **선택** |

### 3.3 처음 생각에서 달라진 점 (요약)
- 코딩 시험 플랫폼 → **일반 시험(객관식+서술형) 플랫폼**. 코드 실행 샌드박스 부담을 덜고 무결성 기능에 집중. 코딩 문제는 고도화 과제.
- "3회 위반 시 종료" → **감독관 확인 후 조치**.
- 1인·2주 개발 일정에 맞춰 1차 범위 축소(v1.1).
- 상세 이력은 `docs/DECISIONS.md`와 회고 문서에 기록.

## 4. 사용자와 사용 장면

### 4.1 사용자
| 사용자 | 목표 |
|---|---|
| 교수자 | 시험을 만들고, 시험을 시작·운영하고, 채점하고, 학생 체감 난이도를 다음 시험에 반영한다 |
| 감독관 | 대시보드를 보고 현장에서 확인·조치한다. 1차에서는 **교수자 계정**으로 감독한다(조교도 교수자 계정을 별도로 발급받아 사용) |
| 학생 | 회원가입 없이 학번과 시험 비밀번호로 들어가 시험을 보고, 무엇이 기록되는지 알고 응시한다 |

### 4.2 대표 시나리오
1. 교수자가 시험(객관식+서술형), 수강생 명단, 무결성 설정을 등록하고 시험 URL을 공유한다.
2. 시험 당일, 교수자가 칠판에 시험 비밀번호(난수)를 적는다.
3. 학생은 URL에 접속해 **학번 + 난수**로 입장 → 본인 확인("○○○ 님이 맞습니까?") → 사전 고지·동의 → 환경 점검(브라우저, 전체화면 진입, 다중 모니터 표시) → **대기실**에서 대기한다.
4. 교수자는 대시보드에서 입장 현황(예: 18/20명)과 입장한 학생 명단을 확인하고 **[시험 시작]**을 누른다. 전원이 동시에 시작한다.
5. 시작 후 도착한 학생은 입장 요청을 보내고, 감독관이 승인하면 공통 종료 시각까지 남은 시간만 응시한다.
6. 응시 중 홍길동(20261234) 학생이 다른 앱으로 전환한다 → 대시보드의 홍길동 카드가 노란색으로 바뀌어 목록 위로 올라오고 "다른 탭/앱으로 이동 (12초)" 기록이 뜬다.
7. 감독관이 홍길동 학생 자리로 가서(이름으로 확인) 확인하고, 필요하면 대시보드에서 경고 메시지를 보내거나 일시정지·종료한다. 조치와 사유가 기록된다.
8. 학생이 제출하면 **종료 설문**(체감 난이도 5점, 교수님께 하고 싶은 말)을 익명으로 남기고 퇴장한다.
9. 교수자는 객관식 자동 채점 결과를 확인하고 서술형을 채점한다. 학생별 신호 타임라인과 조치 기록을 검토하고, 설문 결과(난이도 분포·평균, 의견)를 본다.

## 5. 기능 범위

### 5.1 1차 (필수)
| 영역 | 기능 |
|---|---|
| 시험 관리 | 교수자 로그인(교수자 계정 여러 개 가능), 시험 생성(객관식·서술형), 수강생 명단 등록, 시험 비밀번호(난수) 발급·재발급, 무결성 설정(붙여넣기 기록/차단, 문항·보기 섞기 켬/끔) |
| 입장·대기 | 학번+난수 입장, 본인 확인, 사전 고지·동의, 환경 점검, 대기실, [시험 시작] 버튼, 시작 후 입장 시 **감독관 승인**(지각 표시, 남은 시간만 응시), "시험 시작 후 신규 입장 차단" 옵션 |
| 세션 | 같은 브라우저 세션 토큰의 재접속은 이어서 응시, 다른 기기·브라우저에서 같은 학번 접속 시 차단 후 감독관 승인으로 전환 |
| 응시 | 학생별 문항·보기 순서 섞기, 문항 간 자유 이동, 답안 자동 저장(5초 이하 간격), 재접속 이어 응시, 서버 기준 시간·자동 제출, "기록 중" 표시 |
| 행동 감지 (항상 켜짐) | 탭 전환, 다른 앱 전환, 전체화면 해제, 연결 끊김, 하트비트 공백·이벤트 순번 누락, 이탈 시간, 붙여넣기·드래그 앤 드롭(설정에 따라 기록 또는 차단) + 0단계 실험을 통과한 감지 항목 |
| 위반 카운트·자동 잠금 | 3초 이상 이탈·전체화면 해제·붙여넣기 시도를 위반으로 세고 학생 화면에 "위반 n/5" 표시. **5회마다 자동 잠금**(문항 가림·입력 불가), 감독관 [재개]로만 해제, 해제 시 잠긴 시간 추가 버튼. 네트워크 끊김·신호 지연은 세지 않음 |
| 감독관 | 실시간 대시보드(학생 카드: 학번·이름·상태, 학번순/확인 필요순 정렬), 학생별 신호 타임라인, 경고 메시지·일시정지(화면 잠금, 시간은 계속 흐름)·재개·종료, 학생별 시간 수동 추가, 조치 기록, 여러 학생이 동시에 끊기면 "네트워크 장애 의심"으로 묶어 표시 |
| 채점·결과 | 객관식 자동 채점, 서술형 수동 채점, **교수자 화면에서만** 결과 조회 |
| 종료 설문 | 익명 체감 난이도(5점)·의견, 교수자 화면에 난이도 분포·평균·의견 목록 |
| 배포·검증 | 외부 배포(HTTPS), 20명 동시 응시 부하 테스트, 평가용 데모 계정·데모 시험·접속 안내문 |

### 5.2 0단계 실험 후 포함 여부 결정 (검증 필요)
- 대상: 응시 중 다중 모니터 연결 변화, 화면 분할, 페이지 밖 마우스 이동, 단축키 시도, **AI 사이드바 열림(페이지 영역 축소)**, 전체화면 중 사이드바 동작, AI 확장 프로그램 흔적, 포커스 없는 상태의 입력(에이전트형 AI).
- **일상 행동 오탐 측정**도 함께 한다: 권한 창, OS 알림, 업데이트 창, 노트북 덮개·절전, 한국어 입력기 전환.
- 실험 대상 브라우저: Chrome, Edge.
- 결과는 `docs/STUDY.md`. **채택 항목이 0개인 것도 정상적인 결과**이며, 그 경우 한계로 문서화한다.

### 5.3 2차 (1차 완료 후 남은 시간에 따라 선택)
1. 화면 공유 캡처(시험별 옵션)
2. 서술형 작성 과정 기록·재생
3. 문제 풀(학생별 무작위 추출)
4. 자동 종료 옵션(기본 꺼짐)
5. SEB 접속 '신뢰 높음' 표시
6. 필요 시 재검토: 학생 결과 조회, 조교 역할, 설문 점수 구간별 비교, 일시정지 시 시간 자동 연장, 무결성 설정 확대·프리셋

### 5.4 하지 않는 것
코딩 문제·자동 채점, 웹캠 감독, AI 글 판별기, 문항별 시간 제한, 실시간 화면 영상, SEB 필수화, 대규모(수백 명) 시험. 고도화 후보: 강의실 IP 제한.

## 7. 운영 형태와 제약
- 목적: 기말 프로젝트 평가용 서비스. **성적에 반영되는 공식 시험 운영 계획 없음.**
- 검증 단계: 교수님 시연 → 가상 계정·테스트 데이터 기능 검증 → 20명 부하 테스트 → (가능하면) 자발적 참여자 소규모 시범 운영.
- 시범 운영 전 학교·교수님 측 별도 승인 필요 여부는 **미확인** → 확인 후 진행.
- 1인 개발, AI 코딩 도구 활용, 스펙 주도 개발(PRD → SPEC → 구현).
- **지원 브라우저: Chrome, Edge.** 그 외 브라우저는 환경 점검에서 안내 후 진행 불가. (Whale 등 다른 Chromium 브라우저는 동작할 수 있으나 검증하지 않음)
- 기술 구성: 프런트엔드 React(TypeScript) / 서버 Node.js + Socket.IO / DB PostgreSQL. 상시 구동 호스팅(월 5~10달러 수준).

## 8. 개인정보
- 수집: 학번·이름(명단), 행동 신호, 답안, 조치 기록, 익명 설문. (2차 기능 시 화면 캡처)

- 보관: 행동 신호·조치 기록 90일 후 자동 삭제. 답안·성적·설문의 보관 기간은 SPEC에서 정의.
- 설문: 교수자 화면에서 익명, 의견은 제출 순서를 섞어 표시. 10~20명 소규모에서는 자유 의견 내용만으로 작성자가 짐작될 수 있다는 한계를 설문 화면에 안내한다.
