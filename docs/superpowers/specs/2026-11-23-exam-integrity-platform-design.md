## 1. 의도와 배경

### 1.1 문제
온라인(웹 기반) 시험에서 학생이 생성형 AI 등 외부 도구를 부적절하게 사용하는지 교수자가 직접 볼 수 없다. 흔한 해결책인 "포커스 이탈 감지 + N회 위반 시 자동 종료"는 두 방향으로 실패한다.
- **놓침**: 다른 기기·브라우저 사이드바 등은 잡지 못한다.
- **오탐**: 알림 팝업, 실수로 누른 Alt+Tab 때문에 정직한 학생이 처벌받는다.

또한 **AI 사용 여부를 확정적으로 탐지하는 것은 기술적으로 불가능**하다. 이 플랫폼은 이를 전제로 설계한다.

### 1.2 재정의한 목표
> 부정행위를 "판정"하는 시스템이 아니라, **브라우저 이탈과 브라우저 내 AI 사용의 흔적을 최대한 감지해 감독관에게 실시간으로 알리고, 감독관이 확인·조치하며, 그 과정을 기록으로 남기는 시스템**.

### 1.3 사용 장면 [결정]
- **강의실**에서, 학생은 **개인 노트북 또는 강의실 PC**로 응시한다.
- **사람 감독관**(교수자/조교)이 현장에 있다. 휴대폰·대화 등 물리적 부정행위는 감독관이 담당한다.
- 문항은 **객관식과 서술형 혼합**.
- 규모: **학생 10~20명 동시 응시**.

### 1.3.1 운영 형태 [결정]
- 목적은 **기말 프로젝트 평가용 서비스 개발**이다. 성적에 반영되는 공식 시험 운영 계획은 없다.
- 검증 단계: ① 교수님 대상 서비스 시연 ② 가상 계정·테스트 데이터로 기능 검증 ③ 10~20명 동시 응시 **부하 테스트** ④ 가능하면 자발적 참여자 대상 **소규모 시범 운영**.
- 시범 운영 전 확인 필요: 학교·교수님 측 별도 승인(개인정보 검토, 연구윤리, 서면 동의 등) 필요 여부는 **미확인**이다. 시범 운영 일정은 이 확인 결과에 따른다. 시범 운영 참여자에게는 앱 내 고지·동의와 별도로 참여 동의를 받는다 [제안].

### 1.4 사용자
| 사용자 | 원하는 것 |
|---|---|
| 교수자 | 시험을 쉽게 만들고, 공정하게 채점하고, 의심 상황에 대해 설명 가능한 근거를 갖는 것 |
| 감독관(교수자 또는 조교) | 시험 중 "지금 어느 자리를 봐야 하는지" 바로 아는 것, 현장에서 즉시 조치하는 것 |
| 정직한 학생 | 억울하게 의심받지 않는 것, 네트워크 문제로 답안을 잃지 않는 것, 무엇이 기록되는지 미리 아는 것 |

## 2. 목표 / 비목표 / 실패 조건

### 2.1 목표
1. 10~20명이 동시에 응시 가능한 웹서비스를 **외부에 배포**하고 부하 테스트로 확인한다. 가능하면 자발적 참여자 대상 시범 운영까지 진행한다. [결정]
2. 브라우저·탭 이탈 행동을 신뢰도 높게 감지하고 이탈 시간까지 기록한다.
3. 브라우저 내 AI(사이드바, 확장 프로그램, 에이전트형 조작)의 **흔적**을 가능한 범위에서 감지한다. 가능 범위는 실험으로 확인한다.
4. 감독관이 실시간 좌석 대시보드에서 신호를 보고 조치(경고/일시정지/재개/종료)할 수 있다.
5. 모든 신호와 조치가 시간순으로 기록되어 사후에 검토 가능하다.
6. 감지 기능의 실제 효과를 **우회 시나리오 테스트**로 검증하고 문서화한다.

### 2.2 비목표 (이번 범위에서 하지 않음)
- 코딩 문제와 코드 자동 채점 (고도화 항목) [결정]
- 웹캠 감독, 얼굴 인식 [결정]
- AI 생성 텍스트 판별기(GPTZero 류) 사용 [결정]
- 문항별 시간 제한 / 되돌아가기 금지 [결정]
- 실시간 화면 영상 스트리밍 (고도화 항목) [결정]
- Safe Exam Browser(SEB) 필수화 (고도화 항목) [결정]
- 출제 단계 AI 내성 점검, 제출 후 확인 질문, 학생 소명 절차, AI 허용·기록 모드 등 대화 중 검토한 N1~N9 아이디어 [결정: 제외]
- 대규모(수백 명) 동시 응시 대응

### 2.3 실패 조건 (기술적으로 동작해도 실패로 보는 것)
- 시스템이 스스로 "부정행위/AI 사용"이라고 **판정하거나 단정적 표현**을 쓰는 것.
- 감독관 확인 없이 학생이 불이익을 받는 것 (자동 종료는 교수자가 명시적으로 켠 경우만).
- 네트워크 일시 장애로 학생 답안이 유실되는 것.
- 학생이 무엇이 기록되는지 모른 채 응시하는 것.
- 시험 당일 서버가 잠들어 있거나 접속이 안 되는 것.

## 3. 제약
- 1인 개발, 기말 프로젝트 일정. AI 코딩 도구 적극 활용.
- 프런트엔드 + 백엔드 + DB가 명확히 구분되어야 함 (과제 요건).
- 외부 접속 가능한 배포 필수, HTTPS 필수 (전체화면·화면 공유 API는 보안 컨텍스트에서만 동작).
- 웹 페이지는 설치된 브라우저 확장 목록을 볼 수 없고, OS 수준 행동을 막을 수 없다. → 감지는 "흔적 기반"이다.
- 시험 당일 안정성: 비활성 시 잠드는 무료 서버 사용 불가. 월 5~10달러 수준의 상시 구동 비용을 감수한다.
- SDD: 문서(PRD → SPEC) 기반으로 개발하며, 문서와 코드 변경 이력을 git으로 남긴다.

## 4. 접근법 비교와 선택

### 4.1 전략 수준
| 안 | 내용 | 장점 | 약점 |
|---|---|---|---|
| ① 웹 단독 + 감독 연동 | 일반 브라우저 응시, 이탈·흔적 감지, 실시간 좌석 대시보드, 감독관 조치 | 학생은 링크만 열면 됨, 배포·테스트 쉬움 | 확장 프로그램·사이드바는 막지 못하고 흔적만 감지 |
| ② SEB 필수 | SEB 접속만 허용 | 같은 PC 내 다른 앱·확장·사이드바 실제 차단 | 개인 노트북 설치 부담, Windows/macOS만, 당일 설치 문제 리스크 |
| ③ 사후 검증 중심 | LLM 후속 질문, 답안 유사도 | 차별성 | API 비용·의존, 시험 시간 증가, 사용자 관심 범위 밖 |

**선택: ①** [결정]. ②는 선택 표시 기능(SEB 접속 시 '신뢰 높음' 표시)으로만 흡수하고 필수화는 고도화로 둔다. ③은 제외.
**이유**: 10~20명 실사용이 성공 기준이므로 가장 큰 리스크는 "당일 접속 불가"다. 일반 브라우저 기반이 가장 안정적이고, 사용자의 관심은 "브라우저 이탈과 브라우저 내 AI 사용 흔적 감지"에 집중되어 있다.

### 4.2 감지 이후 처리 방식
- 자동 처벌(N회 위반 시 자동 종료) vs **감독관 확인 후 조치** → **후자** [결정]. 자동 종료는 시험별 옵션(기본 꺼짐).

### 4.3 화면 공유
- 모든 시험 필수 vs **시험별 옵션** → **시험별 옵션** [결정].

### 4.4 기술 스택
| 안 | 구성 | 장점 | 약점 |

## 5. 확정 범위

### 5.0 우선순위 [결정]
| 단계 | 내용 |
|---|---|
| **0. 검증** | 5.5 (b)·(c) 검증 필요 항목 실험 → `docs/STUDY.md` |
| **1차 (필수)** | 핵심 시험 흐름(5.2~5.4, 문항·보기 섞기 포함), 행동 이벤트 수집(5.5 (a) + 검증 통과 항목), 교수자/감독관 대시보드와 조치(5.6), 외부 배포, 부하 테스트 |
| **2차 (우선순위 검토 후 선택)** | 화면 공유 캡처(5.8), 서술형 작성 과정 기록·재생(5.9), 문제 풀, 무결성 설정 프리셋, SEB 신뢰 표시, 자동 종료 옵션 [제안: 마지막 둘도 2차로 분류] |

1차 범위에서도 무결성 설정(5.7)은 1차 기능에 해당하는 항목(전체화면·이탈 감지, 붙여넣기 기록/차단, 다중 모니터, 섞기)만 노출하고, 2차 기능이 추가될 때 설정 항목을 늘린다 [제안].

### 5.1 기술 스택 [결정: B / 세부는 제안]
- 프런트엔드: React + Vite + TypeScript
- 백엔드: Node.js + TypeScript, HTTP API + Socket.IO(실시간)
- DB: PostgreSQL, ORM은 Prisma
- 파일 저장(화면 캡처): Cloudflare R2 (S3 호환) [제안]
- 배포: Railway 또는 Render의 **상시 구동 플랜** + 관리형 PostgreSQL [제안: 최종 선택은 빌더]
- 백엔드 프레임워크(Express/Fastify/NestJS 등), UI 라이브러리, 테스트 도구는 빌더에게 맡긴다.

### 5.2 역할과 계정 [제안]
- 역할: **교수자**, **조교**, **학생**. 감독관 기능은 교수자와, 교수자가 시험에 지정한 조교가 사용한다.
- 로그인: 이메일 + 비밀번호. 교수자·조교 계정은 관리용 시드/초대로 생성, 학생은 자체 가입(이름, 학번, 이메일).
- 학생은 교수자가 공유한 **시험 입장 코드**로 시험에 참여한다.

### 5.3 시험 기능 (교수자)
- 시험 생성: 제목, 안내문, 시작/종료 시각 또는 수동 시작, 제한 시간(시험 전체).
- 문항: **객관식**(단일 정답, 보기 N개) [제안: 1차는 단일 정답만], **서술형**(텍스트).
- 섞기: 학생별 **문항 순서**와 **보기 순서**를 다르게 [결정]. 학생별 시드 기반으로 재접속 시에도 동일 순서 유지 [제안].
- 문제 풀: 문항 그룹에서 학생별로 N개 무작위 추출 [결정].
- 무결성 설정(시험별, 아래 5.7) 및 프리셋(기본/엄격/최소) [제안].
- 좌석 배치: 행×열 격자를 시험(또는 강의실)마다 설정 [제안].
- 채점: 객관식 자동 채점, 서술형은 교수자가 점수 입력 [제안]. 결과 공개 시점은 교수자가 결정 [제안].

### 5.4 응시 흐름 (학생)
1. 로그인 → 입장 코드 입력.
2. **사전 고지·서약 화면** [결정]: 어떤 정보가 기록되는지(이탈 신호, 붙여넣기, 작성 과정, 화면 캡처 여부·보관 기간) 고지하고 동의를 받는다. 동의하지 않으면 응시 불가, 감독관에게 표시.
3. **환경 점검** [결정]: 브라우저 종류, 전체화면 진입, 다중 모니터 여부, (화면 공유 옵션 시) 전체 화면 공유 여부, 좌석 번호 입력. 통과 못한 항목은 감독관 대시보드에 표시하고, 감독관이 입장 허용 여부를 결정 [제안].
4. 응시: 전체화면, 문항 간 자유 이동, 응시 중 상단에 "기록 중" 표시 [결정].
5. **답안 자동 저장**: 변경 시 + 주기적으로 서버 저장, 재접속 시 이어서 응시 [제안: 유실 허용 범위 5초 이내].
6. 제출 또는 시간 종료 시 자동 제출. 남은 시간은 서버 시각 기준 [제안].
7. **시험 시계** [제안]: 학생별 마감 시각을 서버에 저장한다. 감독관이 일시정지하면 정지 시간만큼 해당 학생의 마감이 연장된다. 네트워크 끊김은 자동 연장하지 않고(악용 방지) 끊김 시간을 기록해 감독관에게 표시하며, 감독관이 수동으로 시간 추가할 수 있다.

**지원 브라우저** [제안]: Chromium 계열(Chrome, Edge, Whale)만 허용한다. 환경 점검에서 그 외 브라우저(Safari, Firefox 등)는 통과시키지 않고 설치 안내를 보여주며, 시험 전 공지로도 알린다. 이유: 다중 모니터 감지, 전체 화면 공유 강제 등 핵심 감지 기능이 Chromium에서만 온전히 동작한다.

### 5.5 감지 신호

감지 신호는 시스템이 판정하지 않는 **사건 기록**이다. 각 신호는 `종류, 발생 시각, 지속 시간(해당 시), 당시 문항, 부가 정보`를 갖는다. 표시용 중요도는 정보/주의/경고 3단계 [제안].

#### (a) 브라우저·탭 이탈 — 1차 포함
| 행동 | 신호 | 상태 |
|---|---|---|
| 다른 탭 이동, 창 최소화 | `visibilitychange` | 포함 |
| 다른 앱 전환 | window `blur`/`focus` + 주기적 `document.hasFocus()` 확인 | 포함 |
| 전체화면 해제 | `fullscreenchange` | 포함 |
| 연결 끊김·창 닫힘 | 서버 하트비트 끊김 | 포함 |
| 이탈 지속 시간 | 이탈~복귀 시간 측정 | 포함 |
| 붙여넣기 | `paste` 이벤트(길이 기록). 시험별로 "기록만/차단" | 포함 |

#### (b) 이탈 보조 신호 — [검증 필요]
| 행동 | 후보 신호 |
|---|---|
| 화면 분할로 다른 창 병행 | `resize`, 페이지 밖으로 마우스 이동(`mouseleave`) |
| 두 번째 모니터 | `screen.isExtended`(Chromium 계열), 마우스 가장자리 이탈 |
| 단축키 시도 | 포커스 상실 직전 키 입력(Alt, Win/Meta 등) |

#### (c) 브라우저 내 AI 흔적 — [검증 필요]
| 행동 | 후보 신호 |
|---|---|
| AI 사이드바 열기(Claude in Chrome, Edge Copilot, Gemini, 웨일 사이드바 등) | 브라우저 창 크기(outer)는 그대로인데 페이지 영역(inner)만 줄어드는 변화, 사이드바 클릭 시 포커스 상실 |
| 전체화면 중 사이드바 | 전체화면 해제 또는 사이드바 차단 여부 확인 |
| AI 확장 프로그램이 페이지를 읽음 | `MutationObserver`로 외부 요소 삽입 감지, 문제 텍스트 대량 선택·복사 |
| 에이전트형 AI가 답안 입력 | 페이지에 포커스가 없는데 입력 발생, 마우스 이동 없는 일정 속도 입력 |

**한계 명시**: 사이드바가 열린 것은 감지할 수 있어도 그것이 AI인지는 구분할 수 없다. UI 문구는 "사이드바 열림 의심"처럼 **관찰 사실만** 쓴다.

#### (d) 검증 절차
- SDD 개발의 **첫 작업**으로 (b), (c) 항목을 실험한다. 대상 브라우저는 그때 확정한다(후보: Chrome, Edge, Whale).
- 결과는 `docs/STUDY.md`에 "행동 × 브라우저 × 발생 신호" 표로 기록한다.
- 기준: 신호가 해당 브라우저에서 재현 가능하게 발생하고 일상 행동에서의 오탐이 감독관이 감당할 수준이면 포함, 아니면 제외하고 STUDY에 사유를 남긴다.

### 5.6 감독관 기능
- **실시간 좌석 대시보드** [결정]: 좌석 격자에 학생별 상태(정상/주의/경고/미접속/일시정지/제출) 표시, 신호 발생 시 수 초 내 갱신 [제안: 2초 이내].
- 좌석 클릭 시 학생 상세: 신호 타임라인, (옵션 시) 최근 화면 캡처, 환경 점검 결과.
- **조치** [결정]: 학생 화면에 경고 메시지 전송, 응시 일시정지(학생 화면 잠금)·재개, 응시 종료(현재 답안으로 제출).
- **조치 기록** [결정]: 누가, 언제, 어떤 학생에게, 어떤 조치를, 왜(사유 입력) 했는지.
- 자동 종료 옵션이 켜진 경우에도 종료 사실을 감독관에게 즉시 알린다.
- **자동 종료 집계 규칙** [제안]: 검증이 끝난 (a) 항목 중 "탭 이탈·앱 전환으로 N초 이상 이탈"(기본 5초)과 "전체화면 해제"만 위반 1회로 센다. (b)·(c)의 검증 필요 신호와 붙여넣기는 집계하지 않는다. 횟수 N과 최소 이탈 시간은 교수자가 설정하며, 학생에게는 사전 고지 화면에서 규칙을 보여준다.

### 5.7 시험별 무결성 설정
| 설정 | 기본값 [제안] |
|---|---|
| 전체화면 강제 + 이탈 감지 | 켜짐 |
| 붙여넣기 (기록만 / 차단) | 기록만 |
| 다중 모니터 감지 | 켜짐 (검증 결과에 따라) |
| 문항·보기 섞기 | 켜짐 |
| 서술형 작성 과정 기록 | 켜짐 |
| 화면 공유 캡처 (간격, 보관 기간) | 꺼짐 (켜면 15초 간격, 30일 보관) |
| SEB 접속 시 '신뢰 높음' 표시 | 꺼짐 |
| 자동 종료 (위반 N회) | 꺼짐 |

### 5.8 화면 공유 캡처 (옵션) [결정: 시험별 옵션]
- 응시 시작 시 `getDisplayMedia`로 **전체 화면** 공유를 요구하고, 공유 대상이 모니터 전체가 아니면 진행 불가.
- 지정 간격으로 저해상도 이미지 캡처 → 업로드 → 감독관 상세 화면에서 열람.
- 공유 중지 시 즉시 신호 발생.
- 보관 기간 경과 시 자동 삭제, 열람 이력 기록 [제안].
- [검증 필요] 백그라운드 탭에서의 캡처 지연, macOS 화면 기록 권한 안내 절차, SEB와의 호환성.

### 5.9 서술형 작성 과정 기록
- 서술형 답안의 변경 내역을 시간과 함께 기록하고, 교수자가 채점 화면에서 **재생**할 수 있다.
- 붙여넣기, 장시간 무입력 후 대량 입력 같은 구간을 타임라인에 표시 [제안].
- 저장 방식(키 단위 vs 주기적 스냅샷 차이)은 빌더 결정. 단, 재생 시 흐름을 알아볼 수 있는 해상도(수 초 단위)를 유지.

### 5.10 우회 시나리오 테스트 [결정]
- 알려진 우회 방법(다른 탭, Alt+Tab, 화면 분할, 두 번째 모니터, 사이드바 AI, AI 확장, 에이전트형 브라우저, 직접 타이핑 등)을 실제로 시도하고 무엇이 감지되는지 표로 기록한다.
- 결과는 `docs/STUDY.md`, 해석과 한계는 `docs/RETROSPECTIVE.md`에 반영.

### 5.11 운영 권고 (문서화만)
- 높은 신뢰가 필요한 시험은 강의실 PC + SEB 또는 브라우저 관리 정책(확장·내장 AI 비활성화)으로 운영할 것을 권고.
- 휴대폰·스마트워치·AI 안경 등은 시험 규정과 현장 감독으로 다룬다.

## 6. 비기능 요구사항 [제안]
- 동시 응시 20명 + 감독관 2명 기준에서 안정 동작. 부하 테스트로 확인.
- 대시보드 갱신 지연 2초 이내, 답안 유실 허용 5초 이내.
- HTTPS, 역할 기반 접근 제어(학생은 정답·다른 학생 정보 접근 불가), 비밀번호 해시 저장.
- 시험 시간·제출 마감은 서버가 판단.
- 개인정보: 수집 항목 고지, 화면 캡처 보관 기간 후 삭제, 감독관 열람 기록.
- 보관 기간: 감지 신호·작성 과정 기록·조치 기록은 시험 종료 후 90일, 화면 캡처는 시험별 설정(기본 30일). 기간 경과 시 자동 삭제 작업 수행.

## 7. 고도화 후보
실시간 화면 영상, 코딩 문제 + 자동 채점(샌드박스 필요), SEB 필수 모드, 대화 중 검토된 제외 아이디어 재검토.
