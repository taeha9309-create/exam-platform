# 평가자 시연 안내 (데모)

이 문서는 평가자가 배포된 서비스를 직접 써 볼 때의 접속 방법과, 운영자가 데모 데이터를 준비하는 방법을 설명합니다.
**실제 주소·비밀번호 값은 이 문서에 적지 않습니다.** 제출 문서(또는 제출 안내)에 별도로 기재합니다.

## 1. 평가자 접속 안내 (제출 문서에 옮겨 적는 템플릿)

| 항목 | 값 |
|---|---|
| 서비스 주소 | `<제출 문서에 별도 기재>` |
| 교수자 로그인 | `<서비스 주소>/staff/login` — 이메일 `demo@exam.local`, 비밀번호는 `<제출 문서에 별도 기재>` |
| 학생 입장 주소 | `<서비스 주소>/e/<시험 코드>` — 시험 코드(8자)는 교수자 [진행] 화면의 "학생 입장 주소"에 표시됩니다 |
| 학번 | `20269001` ~ `20269020` (이름 학생01 ~ 학생20) |
| 시험 비밀번호 | `<제출 문서에 별도 기재>` (6자리 숫자) |
| 브라우저 | Chrome 또는 Edge (다른 브라우저는 입장이 막힙니다) |

### 두 브라우저로 시험 흐름 체험하기
교수자와 학생을 동시에 보려면 **서로 다른 브라우저(또는 시크릿 창 + 일반 창)** 를 씁니다. 같은 창에서 교수자와 학생을 오가면 로그인 상태와 학생 세션이 섞일 수 있습니다.

1. 브라우저 A: 교수자로 로그인 → 목록에서 `[데모] 웹 프로그래밍 기말 시험`의 **진행**을 누릅니다. 입장 현황(`준비 완료 인원 / 명단 인원`)과 시험 비밀번호(비밀번호 크게 보기)를 볼 수 있습니다.
2. 브라우저 B: 학생 입장 주소로 접속 → 학번과 시험 비밀번호 입력 → 본인 확인 → 사전 고지 동의 → 환경 점검(전체화면 전환) → 대기실.
3. 브라우저 A에서 입장 현황이 `1/20`으로 바뀐 것을 확인하고 **시험 시작**을 누르면 B가 응시 화면으로 바뀝니다.
4. B에서 답을 입력하고(자동 저장) **제출**, 종료 설문을 냅니다. A에서 **시험 종료** 후 **결과 보기**에서 서술형을 채점하고 **설문 보기**에서 응답을 확인합니다.
5. 시험 시작 이후에 입장하는 학생(지각)은 교수자의 **승인**이 필요합니다. 같은 학번으로 다른 기기에서 다시 접속해도 승인이 필요합니다.

### 꼭 알아 둘 것
- **처음 접속이 느리면 1분 정도 기다리세요.** 무료 서버는 15분 동안 접속이 없으면 잠들어 있다가 다음 접속 때 약 1분에 걸쳐 깨어납니다. 운영자는 시연 몇 분 전에 서비스 주소를 한 번 열어 두세요.
- **교수자는 시험 전에 미리 로그인해 두세요.** 로그인이 429(시도가 너무 많음)로 막히면 다른 네트워크(휴대폰 데이터)를 쓰세요.
- **학생 로그인(입장)은 시연 시작 전에 미리 하세요.** 강의실·학교 와이파이처럼 여러 사람이 같은 공용 IP(NAT)를 쓰는 환경에서는 입장 시도 횟수 제한이 같은 IP로 함께 계산됩니다. 시험 시작 직전에 한꺼번에 입장하면 "시도 횟수가 많습니다" 안내가 나올 수 있으므로, 입장·동의·환경 점검을 마치고 대기실에서 기다리게 하세요.
- 시험 비밀번호는 입장할 때만 필요하며, 한 번 입장한 학생은 새로고침해도 이어서 응시합니다.
- 시연이 끝나면 아래 `demo:reset`으로 데이터를 되돌립니다.

## 2. 데모 데이터 만들기·초기화 (운영자)

데모 교수자·시험·명단을 한 번에 만듭니다. 이미 있으면 **데모 데이터만** 지우고 새로 만듭니다.

```bash
# 개발·테스트 환경 (입장 비밀번호 기본값 246810)
DEMO_STAFF_PASSWORD=<교수자 비밀번호> npm run demo:reset

# 운영(Render 등): 입장 비밀번호를 6자리 숫자로 직접 지정해야 실행됩니다
NODE_ENV=production DATABASE_URL=<운영 DB 주소> DEMO_STAFF_PASSWORD=<교수자 비밀번호> DEMO_PASSCODE=<6자리 숫자> npm run demo:reset
```

- **실행 전에 `DATABASE_URL`이 대상 DB인지 반드시 확인하세요.** 이 명령은 `.env`의 `DATABASE_URL`을 자동으로 읽습니다(`--env-file-if-exists=.env`). 개발 PC의 `.env`가 운영 DB를 가리키면 의도치 않게 운영 DB의 데모 데이터를 지우고 다시 만듭니다(데모 교수자 소유 데이터만 영향을 받지만 시연 중이라면 시험이 초기화됩니다). 대상 DB를 바꿀 때는 위 예시처럼 `DATABASE_URL`을 명령줄로 직접 지정하세요.
- `DEMO_STAFF_PASSWORD`(필수): 8자 이상. 코드·문서·로그에 남지 않습니다. 셸 기록에 남기기 싫다면 `.env`(커밋 금지)에 두거나 프롬프트에서 입력해 주입하세요.
- `DEMO_PASSCODE`: 학생 입장 비밀번호(6자리 숫자). `NODE_ENV=production`에서는 명시하지 않으면 실행을 거부합니다(알려진 기본값이 운영에 남는 것을 막기 위해).
- 만들어지는 것: 교수자 `demo@exam.local`, 시험 `[데모] 웹 프로그래밍 기말 시험`(객관식 5 + 서술형 2, 제한 30분, 상태 "입장 중"), 명단 `20269001`~`20269020`.
- 삭제 범위: 교수자 `demo@exam.local`이 만든 시험(문항·명단·응시·답안·신호·조치·설문 포함)과 그 계정만. 다른 교수자의 데이터는 건드리지 않습니다.
- 실행 후 출력되는 시험 코드로 학생 입장 주소(`/e/<시험 코드>`)를 만듭니다. 초기화할 때마다 시험 코드가 바뀝니다.

## 3. 자동 시나리오 점검 (E2E, 운영자)

핵심 흐름(입장 → 시작 → 응시·저장 → 제출·설문 → 종료 → 채점)을 Playwright로 점검합니다. CI에는 넣지 않고 수동으로 실행합니다.

```bash
npm run build
npx playwright install chromium            # 처음 한 번
# 전용 DB (처음 한 번): CREATE DATABASE exam_e2e 후 마이그레이션
DATABASE_URL=postgresql://exam:exam@localhost:5432/exam_e2e npm run db:deploy -w @exam/server
# 실행: 빌드된 서버를 3100 포트로 띄우고(시작 전에 데모 데이터 재생성) 점검. 값은 이 실행에만 쓰는 임의 값
DATABASE_URL=postgresql://exam:exam@localhost:5432/exam_e2e JWT_SECRET=<32자 이상 임의> DEMO_STAFF_PASSWORD=<임의> DEMO_PASSCODE=246810 npm run e2e
# 배포 URL 대상 (서버를 띄우지 않음, 미리 demo:reset 필요)
PLAYWRIGHT_BASE_URL=https://<서비스 주소> DEMO_STAFF_PASSWORD=<값> DEMO_PASSCODE=<값> npm run e2e
```

**배포 URL 대상 실행은 배포 서버의 데이터를 바꿉니다.** 데모 시험을 시작·종료하고, 학생01의 응시와 설문을 만들고, 데모 교수자 소유의 `[데모] 1분 마감 시험`을 추가합니다. 평가자 시연 직전에는 실행하지 말고, 실행했다면 **끝난 뒤 반드시 `demo:reset`으로 되돌리세요**(시험 코드도 새로 바뀌므로 제출 안내의 입장 주소를 다시 확인).

결과 보고서는 `playwright-report/`, 스크린샷은 `test-results/`에 생깁니다(커밋 제외). 제한 시간 1분짜리 마감 시험이 있어 전체 실행에 약 1분 20초가 걸립니다.
