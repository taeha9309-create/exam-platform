# 회고 (RETROSPECTIVE)

> **초안이다.** 사실(숫자·결정·결과)은 저장소 기록(`docs/DECISIONS.md`, PR·이슈, `docs/STUDY.md`)에서 가져왔다. "느낀 점"과 "다시 한다면" 칸은 작성자가 본인의 말로 고쳐 쓴다(`[작성자 기입]` 표시).

## 1. 무엇을 만들었나
강의실 시험 중 **브라우저 이탈과 브라우저 안의 AI 흔적**을 감지해 감독관 대시보드에 보여 주는 시험 무결성 플랫폼(React + Node + Socket.IO + PostgreSQL). 시스템은 판정하지 않고 **관찰한 사실**을 보여 주며, 조치(확인·경고·일시정지·종료)는 감독관이 한다.
- 학생: 입장 → 동의·환경 점검 → 대기실 → 응시(자동 저장, 전체화면 게이트, 위반 5회 자동 잠금) → 제출·설문
- 교수자: 시험 관리, 실시간 대시보드(학생 카드·타임라인·네트워크 장애 묶음 배너), 감독관 조치와 기록

## 2. 개발 방식: 스펙 주도 개발(SDD) + 하네스
| 단계 | 산출물 |
|---|---|
| PRD → SPEC | `docs/PRD.md`, `docs/SPEC.md`(v1.0 → v1.4.4), 결정과 근거 `docs/DECISIONS.md`(D-001~D-031, ADR-001~014) |
| 계획 | 계획 0(감지 실험), 1(핵심 응시 흐름), 2(감지·대시보드), 3(검증) |
| 실행 | 이슈 = 작업 지시서 → Operator(구현·테스트) → Reviewer(SPEC·보안 검토, 중요 작업은 Opus) → CI → **사용자만 병합** |
| 안전장치 | 보호 문서 변경은 사용자 승인 라벨, `중요-리뷰` PR의 SHA 묶인 승인 댓글, 최신 main 기준 필수 검사(`docs/harness/VERIFICATION.md`) |

| 변경 | 이유 | 기록 |

## 4. 감지 실험에서 알게 된 것 (요약, 상세는 STUDY)
- 탭 전환은 `visibilitychange`와 `blur` 모두 잡히지만, **화면 분할은 `hidden`이 0/5**여서 `blur`가 필요하다. SPEC의 `LEAVE`는 이미 둘을 함께 쓴다.
- Gemini 사이드바는 창 바깥 너비는 그대로, 페이지 너비만 약 410px 줄어드는 형태로 5/5 관찰됐다. 전체화면에서는 사이드바가 열리지 않는다(5/5).
- **Playwright 같은 자동화는 포커스를 에뮬레이션해 탭 전환·포커스 이탈을 가린다.** 자동화 결과(0)는 폐기하고 사람이 한 실험만 집계했다. E2E는 이탈을 흉내 내고(실제 앱 리스너는 동작), 실제 브라우저 감지는 사람 실험이 맡는다.

## 5. 품질 활동에서 배운 것
- 리뷰(특히 Opus 보안 검토)가 **동시성·저장 상한·큐 상한·재연결 경쟁** 같은 구현자가 놓친 결함을 반복해서 찾았다. 재시도 한도 3회 규칙은 대부분 1~2회 안에 끝났다.
- CI에서만 실패한 테스트(타이밍 의존)가 있었다 → 시계 독립적 단정과 CPU 부하 상태 재검증으로 해결.
- 변이 시험(구현을 일부러 틀리게 바꿔 테스트가 잡는지 확인)이 "테스트가 있다"와 "테스트가 동작을 고정한다"를 구분해 주었다. Operator가 테스트를 먼저 쓰지 못한 곳은 변이 시험으로 대신 확인했다.
- 하네스 마찰: 훅의 오탐(명령 텍스트에 특정 단어가 있으면 차단), 병합이 늦어질수록 늘어나는 `update-branch` 재검증, `중요-리뷰` 승인의 SHA 묶임. 규칙을 약화하지 않고 작업 방식(본문 파일 사용, 명령 분리)을 바꿔 대응했다.

## 6. 한계와 남은 위험
- 감지는 **브라우저가 알려 주는 것까지만** 본다. 다른 기기·두 번째 모니터를 눈으로만 읽는 경우, 천천히 조금씩 줄이는 창 크기 변화는 못 잡는다.
- 실험은 Chrome 158, 모니터 1대, 시나리오당 5회에 한정(Edge·일상 행동 대부분 미실험).
- 무료 호스팅: 15분 유휴 후 잠듦, 무료 DB 30일 만료(ADR-013).
- 부하 검증 수치는 로컬 환경 기준이며 Render 무료 인스턴스 성능과 다르다(STUDY의 측정 절 참고).
