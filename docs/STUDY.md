## 1. 브라우저 이탈 감지 API

### 몰랐던 것
- 탭을 바꾸는 것(`visibilitychange`)과 창 포커스를 잃는 것(`blur`)이 **다른 이벤트**라는 점. 다른 앱으로 Alt+Tab 했을 때 어느 쪽이 발생하는지 모른다. (가설) 탭 전환은 둘 다, 다른 앱 전환은 `blur`만 발생한다.
- 전체화면(`requestFullscreen`)은 **사용자의 클릭이 있어야** 들어갈 수 있고 ESC로 언제든 풀린다. 그래서 "강제"가 아니라 "진입 요구 + 해제 감지"만 가능하다.
- 탭이 백그라운드에 있으면 브라우저가 타이머를 늦춘다. 이탈 시간을 타이머로 재면 부정확하므로 **떠난 시각과 돌아온 시각의 차이**로 계산해야 한다.
- 이벤트가 누락될 수 있어 `document.hasFocus()`를 1초마다 확인해 보완할지 모른다.

### 공부한 자료와 방법
- MDN: [Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API), [Window: blur event](https://developer.mozilla.org/en-US/docs/Web/API/Window/blur_event), [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API) (링크는 읽은 뒤 본인이 확인)
- 읽은 내용만으로 판단하지 않고, 모든 후보 이벤트를 시각과 함께 기록하는 **실험 페이지**를 만들어 직접 확인하는 방식으로 공부했다.

### 서비스에 적용한 과정과 결과
- 판정 로직(이탈·복귀 짝 맞추기, 지속 시간 계산)을 DOM과 분리한 순수 함수로 만들어 Node에서 단위 테스트했다(`experiments/detection-lab/detectors.js`).
- 이벤트가 뒤섞여 들어와도 시각순으로 처리하도록 만들었다.
- 실험 결과: (실험 후 기입)

| 행동 | 브라우저 | 발생한 이벤트·신호 | 횟수 | 판단 |
|---|---|---|---|---|
| 다른 탭으로 이동 | Chrome | (실험 후 기입) | /10 | |
| 다른 탭으로 이동 | Edge | (실험 후 기입) | /10 | |

## 2. 브라우저 안의 AI(사이드바·확장 프로그램) 흔적 감지 실험

### 몰랐던 것
- 웹 페이지는 **설치된 확장 프로그램 목록을 볼 수 없다**(브라우저 보안 정책). 그래서 "AI를 켰다"를 직접 알 수 없고, 켤 때 생기는 **흔적**만 잡을 수 있다.
- (가설) AI 사이드바가 열리면 브라우저 창(outer) 크기는 그대로인데 페이지 영역(inner)만 줄어든다. 창을 직접 줄이면 outer도 변하므로 구별할 수 있다.
- (가설) 일부 확장은 페이지에 요소를 끼워 넣어 `MutationObserver`로 잡힌다. 확장마다 달라서 일반적인 방법은 아닐 수 있다.
- (가설) 에이전트형 AI가 입력을 대신하면 "페이지에 포커스가 없는데 입력이 발생"하는 모순이 생긴다.
- 사이드바가 열린 것은 잡아도 **그것이 AI인지는 구분할 수 없다.** 화면 문구는 관찰 사실("사이드바 열림 의심")만 써야 한다.

### 공부한 자료와 방법
- MDN: [MutationObserver](https://developer.mozilla.org/en-US/docs/Web/API/MutationObserver), [Screen.isExtended](https://developer.mozilla.org/en-US/docs/Web/API/Screen/isExtended)
- 실험 페이지에서 시나리오별로 **Chrome·Edge 각 10회** 반복하고 JSON으로 저장 → 집계 스크립트로 표를 만들었다.

### 서비스에 적용한 과정과 결과
- 실험 환경: OS (실험 후 기입), Chrome 버전 (실험 후 기입), Edge 버전 (실험 후 기입), 모니터 수 (실험 후 기입), 사용한 AI 사이드바·확장 (실험 후 기입)
- 집계 결과(`summarize.js` 출력): (실험 후 기입)
- **채택/제외 판단과 근거:** (실험 후 기입). **채택 항목이 0개인 것도 정상적인 결과**이며, 그 경우 한계로 문서화한다.
- 채택된 항목은 SPEC 5.1에 신호 행으로 추가(버전 올림)하고 결정 기록에 남긴다.

## 3. 커서가 페이지 밖으로 나가면 화면 가림 (SPEC 5.6)

### 몰랐던 것
- 전체화면 + 모니터 1대에서는 커서가 원래 페이지 밖으로 나갈 수 없다. (가설) 그래서 이 신호는 주로 **두 번째 모니터로 이동**하거나 **AI 사이드바 위에 커서를 올린 경우**를 잡는다.
- 브라우저 기본 팝업(`<select>` 등)이 열릴 때 `mouseleave`가 발생하는지 모른다.

### 공부한 자료와 방법
- 실험 페이지에 "커서 이탈 시 화면 가림" 옵션과 브라우저 기본 `<select>`를 넣어 직접 확인한다.

### 서비스에 적용한 과정과 결과
- 1초 미만은 기록하지 않고, 1~3초 정보 / 3~15초 주의 / 15초 초과 경고로 나누는 판정 함수를 구현·테스트했다.
- 결과: (실험 후 기입). 오탐이 채택 기준을 넘으면 제외한다.

| 행동 | 브라우저 | POINTER_LEAVE | 판단 |
|---|---|---|---|
| 커서를 두 번째 모니터로 이동 | Chrome / Edge | (실험 후 기입) | |
| 커서를 AI 사이드바 위에 올리고 읽기만 | Chrome / Edge | (실험 후 기입) | |
| 터치패드로 입력 중 커서가 가장자리로 밀림(오탐) | Chrome / Edge | (실험 후 기입) | |
| 전체화면에서 커서를 화면 상단에 댐(오탐) | Chrome / Edge | (실험 후 기입) | |

### 공부한 자료와 방법

## 5. 구현 전에 실험 페이지부터 검증한 방법 (헤드리스 브라우저)

### 몰랐던 것
- 실험 페이지 자체에 버그가 있으면 실험 결과를 믿을 수 없다. 사람이 하는 실험 전에 페이지가 "이벤트를 받으면 올바르게 기록하는지"를 먼저 확인해야 한다.

### 공부한 자료와 방법
- Chrome DevTools Protocol(CDP): 헤드리스 Chrome을 원격 디버깅 포트로 띄우고, WebSocket으로 접속해 페이지에서 코드를 실행한다.

### 서비스에 적용한 과정과 결과
- 일회용 스크립트로 헤드리스 Chrome 158을 구동해 이벤트(탭 숨김, blur, 창 크기 변화, 커서 이탈, DOM 삽입, 포커스 없는 입력, 선택)를 코드로 발생시켰다.
- 결과: 후보 신호 7종이 기록되고, 이 페이지가 만든 요소는 `DOM_INJECTED`에서 제외되며, 기록 정지 중에는 이벤트가 쌓이지 않고, 페이지 오류는 0건이었다.
- **한계:** 이벤트를 코드로 발생시킨 것이라 "받으면 기록한다"까지만 증명한다. 실제 브라우저가 어떤 이벤트를 주는지는 사용자의 실험으로만 알 수 있다(전체화면 해제, 두 번째 모니터 등은 이 방법으로 검증하지 못했다).
