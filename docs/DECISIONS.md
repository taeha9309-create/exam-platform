# 기술 결정 (ADR)

위 표는 결정의 목차이고, 이 절은 기술 결정의 근거를 ADR(Architecture Decision Record) 형식으로 남긴다.
형식: 배경 / 결정 / 검토한 대안 / 결과(장단점) / 승인.
"승인"이 적힌 ADR만 확정이다. 확정된 ADR을 바꿀 때는 새 ADR을 추가하고 이전 ADR에 "대체됨: ADR-xxx"를 적는다.

## ADR-001 런타임: Node.js 24 LTS
- 배경: SPEC v1.0은 Node 20 LTS로 적었으나 개발 PC에 Node 24.20이 설치되어 있다. Node 20은 2026-04 지원 종료.
- 결정: Node.js 24 LTS. 배포 환경도 24로 고정(`engines` 필드).
- 대안: Node 20(지원 종료), Node 22 LTS(별도 설치 필요).
- 결과: 로컬·배포 버전 일치. **결정 기록 없이 SPEC을 먼저 고친 절차 위반이 있었음**(2026-11-25 검토에서 발견, 이 ADR로 보완).
- 승인: SPEC v1.3 승인(2026-11-25), 기록 보완 승인(2026-11-25)

## ADR-002 저장소 구조: npm workspaces 모노레포 + `shared` 패키지
- 배경: 클라이언트와 서버가 이벤트 이름·상태 값·오류 코드를 똑같이 써야 한다. 다르면 실시간 기능이 조용히 깨진다.
- 결정: 한 저장소에 `shared`·`server`·`client` 작업 공간. 공유 타입·상수는 `shared`에만 정의.
- 대안: 저장소 분리(배포·버전 관리 부담), 타입 복사(불일치 위험), Turborepo·Nx(1인 2주 규모에 과함).
- 결과: 한 번의 변경이 양쪽에 반영. 단, 여러 작업이 `shared`를 동시에 고치면 병합 충돌 → 병렬 작업 시 `shared` 변경은 Coordinator가 병합할 때만 수행.
- 승인: SPEC v1.3 / 계획 1 승인(2026-11-25)

## ADR-003 데이터 계층: PostgreSQL 16 + Prisma, 테스트는 실제 DB
- 배경: 상태 전이·동시 시작 같은 규칙은 DB 트랜잭션과 조건부 업데이트에 의존한다.
- 결정: PostgreSQL 16, Prisma ORM. 로컬은 Docker Compose. 통합 테스트는 모의 객체 대신 실제 테스트 DB(`exam_test`)를 테스트마다 초기화해 사용.
- 대안: SQLite(배포 DB와 동작 차이), 모의 DB(동시성 버그를 못 잡음), Drizzle·TypeORM(AI 도구 친숙도·문서 측면에서 Prisma 선택).
- 결과: 테스트가 실제 동작을 검증. 테스트가 느려지고 Docker가 필요.
- 승인: SPEC v1.3 / 계획 1 승인(2026-11-25)

## ADR-004 교수자 인증: JWT를 httpOnly 쿠키에 저장
- 배경: 교수자는 로그인 계정이 있고, 같은 도메인에서 화면과 API를 함께 제공한다(D-017).
- 결정: bcrypt 해시 비밀번호. 로그인 시 12시간짜리 JWT를 `staff_token` httpOnly·Secure·SameSite=Lax 쿠키로 발급. 소켓 연결도 같은 쿠키로 인증.
- 대안: localStorage 토큰(XSS 시 탈취 위험), 서버 세션 저장소(테이블·정리 작업 추가).
- 결과: 페이지 스크립트가 토큰을 읽을 수 없음. 로그아웃해도 토큰 자체의 즉시 무효화는 안 됨(12시간 만료로 감수).
- 승인: SPEC v1.3 승인(2026-11-25)

## ADR-005 학생 세션: 무작위 토큰 + 해시 저장 + localStorage
- 배경: 학생은 계정 없이 학번+시험 비밀번호로 들어오고(D-008), 새로고침·재접속은 이어서, 다른 기기는 감독관 승인으로 처리해야 한다.
- 결정: 본인 확인 시 32바이트 무작위 토큰 발급, 서버에는 SHA-256 해시만 저장, 브라우저는 `localStorage`의 `exam:{examCode}:token`에 보관. 다른 토큰의 접속은 `pendingToken`을 받아 2초마다 확인하고, 감독관이 승인하면 세션을 이어받는다.
- 대안: 쿠키(한 브라우저에서 교수자·학생 화면을 함께 시연할 때 충돌), 기기 지문(부정확·개인정보).
- 결과: DB가 유출돼도 토큰을 재사용할 수 없음. localStorage를 지우면 같은 브라우저도 "다른 기기"로 취급되어 승인 필요.
- 승인: SPEC v1.3 승인(2026-11-25). 승인 후 확인 방식은 SPEC v1.4에 반영.

## ADR-006 실시간: 서버가 상태의 원본, 스냅샷 + 변경분, 답안은 소켓 + rev
- 배경: 감독관 화면과 학생 화면이 새로고침·재연결 후에도 같은 상태를 보여야 한다.
- 결정: Socket.IO 방(`exam:{id}:staff`, `exam:{id}:students`, `attempt:{id}`). 연결 시 전체 상태(스냅샷)를 보내고 이후 변경분만 보낸다. 답안 저장은 소켓 + ack, 문항별 `rev`가 저장값보다 작으면 거부.
- 대안: 주기적 폴링(지연·부하), 클라이언트가 상태를 계산(재연결 시 불일치).
- 결과: 재연결 처리가 단순해짐. 서버가 재시작되면 모든 소켓이 다시 연결해야 함(클라이언트 자동 재연결로 감수).
- 승인: SPEC v1.3 승인(2026-11-25)

## ADR-007 시간과 동시성: 1초 주기 마감 점검, 조건부 업데이트로 시험 시작
- 배경: 학생별 마감(공통 마감 + 추가 시간)을 지켜야 하고, 두 교수자가 동시에 [시험 시작]을 누를 수 있다.
- 결정: 서버가 1초마다 마감이 지난 응시를 제출 처리한다. 시험 시작은 `status = OPEN`일 때만 바뀌는 조건부 업데이트로 한 번만 성공시킨다.
- 대안: 학생마다 타이머 생성(서버 재시작 시 유실), 분산 잠금(규모에 과함).
- 결과: 서버가 재시작돼도 마감이 지켜짐. 최대 1초 지연.
- 승인: SPEC v1.3 / 계획 1 승인(2026-11-25)

## ADR-010 하네스 역할과 모델 라우팅
- 배경: 하네스 엔지니어링 학습과 비용 관리를 위해 역할과 모델을 나눈다.
- 결정:
  - Coordinator = 메인 세션(Sonnet). 상태·의존성·위임·병합 담당. 직접 구현은 계획 0의 1~3번, 계획 1의 1·2·17a번(뼈대)만.
  - Operator = `.claude/agents/operator.md`(기본 Sonnet, 1~2개 파일의 단순 작업은 호출할 때 Haiku).
  - Reviewer = `.claude/agents/reviewer.md`(Sonnet, 중요 작업의 보안 검토는 호출할 때 Opus + `security-review`).
  - Advisor = `.claude/agents/advisor.md`(Opus, 읽기 전용, 제안만). Claude Code의 `/advisor` 기능은 쓰지 않는다(실험 기능이고 호출 시점을 강제할 수 없음).
  - 구현·리뷰 절차는 Superpowers `subagent-driven-development`를 재사용하되, **재시도 한도는 3회**(1~2회 Operator 수정, 3회째는 Advisor 조언 후 재시도, 그래도 실패하면 사용자 보고). 프로젝트 규칙이 스킬 기본값(5회)보다 우선한다.
- 대안: 전부 한 모델(비용·학습 효과 없음), Workflow 도구·Agent Teams(실행 중 사용자 승인 불가, 실험 기능, 토큰 비용 큼).
- 결과: Haiku는 다단계 작업에서 턴이 2~3배 늘 수 있어 단순 작업에만 쓴다.
- 승인: 사용자(2026-11-25, 최소 하네스 구성안)

## ADR-011 하네스 상태와 실행 기록: 이슈 라벨 + 진행 기록 + PR
- 배경: 세션이 끊겨도 복구해야 하고, 작업별 모델·시간·재시도·리뷰·토큰을 기록해야 한다. 별도 로깅 시스템은 만들지 않는다.
- 결정: 작업 상태의 원본은 GitHub 이슈 라벨(`상태:*`). 진행 중 세부는 Superpowers 진행 기록(ledger). 작업별 실행 기록은 PR 본문의 "하네스 기록" 표(PR 템플릿)에 남긴다. 토큰은 서브에이전트 완료 알림에 표시되는 사용량을 옮겨 적는다.
- 대안: 별도 상태 파일·DB(중복), 외부 관측 도구(과함).
- 결과: 기록이 GitHub에 남아 발표·회고 자료가 됨. 메인 세션(Coordinator)의 토큰은 작업별로 나눌 수 없어 사이클 단위로 `/usage` 값을 적는다.
- 승인: 사용자(2026-11-25, 하네스 추가 요구사항)

## ADR-012 배포: Railway 설정 파일 없이 서비스 설정 + 표준 스크립트
- **부분 대체됨: ADR-013**(호스팅이 Render로 변경되어 Railway·Pre-deploy 부분은 더 이상 쓰지 않는다. "설정 파일 없이 대시보드 설정 + 표준 스크립트" 방침은 유지).
- 배경: 계획서는 `railway.json`으로 빌드·시작 명령을 정하기로 했다. 조사 중 Railway의 Config as Code(`railway.json`/`railway.toml`)가 폐지됨을 발견했다. 공식 문서 원문: "Existing Config as Code files stop being read on 2026-12-01 (hard cutoff)", "New services cannot opt into Config as Code". 이 프로젝트의 마감(12/07~12/14)은 그 이후다.
- 결정: 설정 파일을 만들지 않는다. Railway 서비스 설정(대시보드)에서 Build `npm run build`, Start `npm start`, **Pre-deploy Command `npm run db:deploy -w @exam/server`**를 지정하고, 루트 `package.json`의 표준 스크립트(`build`, `start`)와 `.node-version`을 쓴다. 변수는 `DATABASE_URL`(`${{Postgres.DATABASE_URL}}` 참조), `JWT_SECRET`, `NODE_ENV=production`. 절차는 README "배포 (Railway)".
- 대안: `railway.json`(2026-12-01 이후 무효, 새 서비스는 불가), Infrastructure as Code(`.railway/railway.ts`, 이 규모에는 과함), 시작 명령에 마이그레이션 포함(실패 시 배포가 멈추지 않고 앱이 죽은 채 재시작 반복).
- 결과: 설정이 코드로 버전 관리되지 않아(대시보드에만 존재) README 절차에 의존한다. 대신 마이그레이션이 **새 버전이 뜨기 전에 실행되고 실패하면 배포가 중단**된다(Pre-deploy). 폐지 일정과 무관하게 동작한다.
- 승인: 사용자(2026-11-26, PR #35 병합). 이 기록은 PR #35에서 보호 파일 변경을 피하려고 후속 문서 PR로 미뤘다.

## ADR-013 배포 플랫폼: Railway에서 Render 무료로 변경
- 배경: 사용자가 유료 호스팅 없이 배포하기를 원했다(2026-11-27). 후보를 공식 문서로 확인했다. Railway: 월 5달러(Hobby)가 안정적이고, 무료 플랜은 월 1달러 사용량·유휴 시 잠듦·문서 간 설명이 달라 불확실. Vercel: 서버리스 함수 기반이라 이 프로젝트의 상시 구동 전제(1초 주기 마감 점검 `setInterval`, 메모리 기반 로그인·입장 제한기, 소켓 연결 상태)와 맞지 않아 구조를 다시 짜야 한다(코드 구조에 근거한 판단이며 Vercel 문서는 WebSocket을 공개 베타로 지원하나 연결이 함수 최대 실행 시간에 끊긴다고 명시). Render: 상시 구동 Node 웹 서비스와 PostgreSQL을 무료로 제공.
- 결정: Render 무료 웹 서비스 1개 + Render 무료 PostgreSQL 1개(같은 리전, 내부 주소로 연결), 같은 도메인 서빙 유지. 설정 파일(`render.yaml`)은 만들지 않고 대시보드 설정 + 루트 `package.json` 표준 스크립트(ADR-012의 방침 유지). Build `npm ci && npm run build`, **Start `npm run db:deploy -w @exam/server && npm start`**(무료 인스턴스는 Pre-deploy Command를 쓸 수 없으므로 마이그레이션을 시작 명령 앞에 둔다. 적용할 마이그레이션이 없으면 바로 끝난다), Health Check `/api/health`, 변수 `DATABASE_URL`(Internal URL)·`JWT_SECRET`·`NODE_ENV=production`, 선택 `TRUST_PROXY_HOPS`(1~3, 기본 1).
- 대안: Railway 유료(안정적이나 월 비용), Railway 무료 플랜(조건 불확실), Vercel(서버리스 구조와 불일치), 다른 무료 호스팅(조사하지 않음).
- 결과: 비용 0원, 설정 변경이 작다(코드 변경은 프록시 홉 수 환경변수뿐). 대신 제약이 생긴다. (1) **15분간 트래픽이 없으면 잠들고** 다음 접속 때 약 1분에 걸쳐 깨어난다(시험 중에는 소켓 메시지가 오가 유지) → 시연·평가 전에 주소를 한 번 열어 깨운다. (2) **무료 DB는 생성 30일 뒤 만료**(14일 유예 뒤 삭제), 백업 없음, 1GB → DB를 제출 시점에 맞춰 만들고 만료 전 새 DB에 `demo:reset`으로 데이터를 다시 넣는다. (3) 시작 때마다 마이그레이션이 실행되고 실패하면 서비스가 시작되지 않는다. (4) Render 프록시는 `X-Forwarded-For`를 덮어쓰지 않고 덧붙인다는 보고가 있고 홉 수는 공식 문서에서 확인하지 못했다 → 배포 후 로그인 시도 제한으로 검증하고 `TRUST_PROXY_HOPS`로 조정.
- 승인: 사용자(2026-11-27, "Render로 하자"). 보호 문서 변경이므로 PR의 `문서변경-승인` 라벨은 사용자가 직접 붙인다.
